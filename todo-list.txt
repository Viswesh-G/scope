# Scope — What's left to build

---

## What's already done

The CLI is fully working. Here's what exists right now:

- scope search   — concurrent regex search, worker stats, metrics table
- scope search --profile   — CPU + memory pprof, written to .scope/
- scope compare   — head-to-head benchmark vs ripgrep (mean, P50/P95/P99, Mann-Whitney U, sparkline)
- scope audit   — chains stats + deps + dupes into one command
- scope history   — full history (13 subcommands: stats, top, slowest, fastest, recent, pattern, path, replay, export, prune, clear)
- scope config   — color customisation, saved to ~/.scope-config.yaml
- scope ignore   — .scope-ignore management (init, add, remove, list)
- scope stats / deps / dupes / graph   — codebase analysis tools

---

## What's left (in priority order)

### 1. HTML Report  ← do this next

```bash
scope search -p "github" --html report.html
```

Opens in a browser. Would show:

- Matches
- Metrics (files, bytes, duration)
- Worker stats table
- Load balance chart
- Top hotspots

This is the next big feature. Medium difficulty — mostly just writing the HTML template and wiring up a new flag.

---

### 2. Live Dashboard

```bash
scope serve
```

Starts a local server at localhost:8080. Shows live data from .scope/history.json:

- search history
- throughput over time
- worker utilization
- hotspots
- extension stats
- dependency stats

Grafana-like, but built from scratch in Go. Hard — needs an HTTP server, JSON API, and a frontend (could be plain HTML+JS).

---

### 3. Flamegraph Viewer

```bash
scope flame latest
```

Opens the most recent .scope/cpu.pprof in the browser as a flamegraph (calls go tool pprof -http internally). The main value here is the UX — no one wants to remember the pprof command.

Could also auto-generate SVG flamegraphs:

```
.scope/cpu.svg
.scope/mem.svg
```
