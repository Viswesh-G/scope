# Next Major Milestone

You now have a useful CLI.

The next jump is:

## Self-Profiling

This is where Scope becomes unique.

---

# 1. pprof Integration

Add:

```bash
scope search -p "github" --profile
```

or

```bash
scope profile search -p "github"
```

Generates:

```bash
.scope/
    cpu.pprof
    mem.pprof
```

Code:

```go
import "runtime/pprof"

f, _ := os.Create("cpu.pprof")
pprof.StartCPUProfile(f)

defer func() {
    pprof.StopCPUProfile()
    f.Close()
}()
```

# 9. Flamegraphs

The feature that changes the project from "CLI utility" to "systems project".

```bash
scope search -p github --profile
```

Generates:

```text
cpu.svg
memory.svg
```

Then:

```bash
scope flame latest
```

opens browser.

Shows:

```text
searchFile()
    └── regexp.Match()
          └── ReadFile()
```

Now you're building observability tooling.

---

# Priority Order

Do these in order:

```text
4. Benchmark Command       (medium)
5. pprof Integration       (medium)
6. Compare Against rg      (medium)
7. HTML Reports            (medium)
8. Dashboard Server        (hard)
9. Flamegraphs             (very hard)
```

If your goal is a standout systems/concurrency/observability project, the biggest value now is **Benchmark → pprof → Flamegraphs**. Those are the features that transform Scope from a grep clone into a self-observing search engine.
